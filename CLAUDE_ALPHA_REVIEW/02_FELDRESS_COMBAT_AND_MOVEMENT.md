# 02. Feldress 전투 및 이동 시스템

- 작성일: 2026-11-20 · 버전 v0.1 · 기준 `main` / `9d2d42b`
- 상태: 모든 제안 `PROPOSED — NOT APPROVED`. 수치는 `초기 가설`. 라벨: KEEP / CHANGE / DEFER / REMOVE / NEW

---

## 1. 목표와 설계 원칙

- 재미의 핵심은 "기체를 몰며 갈고리·대시·에너지·탄약을 저울질하는 긴장감"과 "피해 부위를 보고 판단하는 순간"이다.
- 원칙 1: **이동감은 클라이언트가 즉시 만들고, 결과(피해·부착·에너지·탄약·재화)는 서버가 확정한다.** (C-01)
- 원칙 2: **기체 종류 차이는 데이터(표)로만 표현하고 코드 경로는 하나로 유지한다.** 알파에서 기체 1종 제품 + 내부 검증용 1종.
- 원칙 3: **물리 시뮬레이션은 최소화한다.** 기체 본체 1개 + 앵커된 부품, 줄과 투사체는 물리 파트 금지. (C-02, C-04)

## 2. 이동 (WASD, 마우스 회전, 스트레이프)

### 기존 결정 (KEEP)
WASD 이동, 마우스 방향 회전, 측면 입력으로 기체가 강제 회전하지 않음, 중량에 따른 회전·관성 차이, 점프 가능, 공중 회전은 관성 영향.

### 제안 구현
- 기체 본체: `VehicleController` 모듈. 입력은 `Input Action System`으로 받는다(모바일·PC·컨트롤러 공통 바인딩)【사실: 공식 문서가 액션 기반 입력 제공】.
- 물리: 본체 단일 `BasePart` + `VectorForce`/`LinearVelocity` 기반 가속·감속 곡선. 다리는 시각 애니메이션, 충돌 판정은 본체 박스 1개 + 보조 레이캐스트 4개(지면 접지)【추론: 다리별 물리 제약을 피해 프레임 비용 절감】.
- 네트워크 소유: 탑승자가 소유. 서버는 P-MOVE 검증(`01` §2.1).
- 검증 샘플: 0.1초 주기 기본, 측정 후 조정【검증 필요】.

| 항목 | 기체별 데이터 | 알파 초기 가설 |
|---|---|---|
| 최대 전진 속도 | 기체 값 | 30 studs/s |
| 후진 비율 | 기체 값 | 전진의 50% |
| 회전 속도 | 기체 값 | 120°/s |
| 가속 시간(0→최대) | 중량 | 0.6~1.2s |
| 점프 높이(최대 차징) | 기체 값 | 12~20 studs |

- 수치 근거: 1 stud ≈ 28cm 가정이면 30 studs/s ≈ 30 km/h 수준으로 '중장갑 기체'의 묵직함에 맞춘 출발점(【검증 필요】, 실제 체감으로 재조정).

### 점프 차징 (KEEP 규칙, 구현 제안)
- 버튼 홀드 시간을 서버 시작 시각 기준으로 **클라이언트가 보고**, 서버는 최대 차징 시간을 넘는 값을 클램프한다.
- 실제 점프 순간에 에너지 1회 차감(서버). 차징 중 피격은 무시(KEEP).

## 3. 대시 (KEEP 핵심 규칙, 수치 NEW)

- 방향: 기체 정면 고정(KEEP). 대시 중 회전·방향 조정 불가(KEEP).
- 지상/공중 대시는 **같은 쿨다운 공유**(KEEP), 공중 전용 상수 세트(C안: 별도 성능) 적용. 알파에서는 공중 대시 상수를 지상과 같게 두고 차이는 DEFER.
- 구현: 서버가 대시 시작 요청을 검증(에너지 최소치, 쿨다운, 상태) → 승인되면 탑승자 클라이언트가 전용 속도 곡선을 적용하고, 서버는 대시 지속시간과 시작 위치 변화량을 검증.
- 대시 종료 충돌: 벽·적 Legion에 충돌하면 즉시 종료(KEEP). 충돌 판정은 클라이언트 `Touched` 대신 **서버 주기 레이캐스트 쿼리**로 판정하여 악용을 막는다(C-01).
- 초기 가설: 거리 25 studs, 지속 0.6s, 쿨다운 4s, 대시 중 에너지 초당 소모 12.

## 4. 갈고리 (KEEP 동작, 구현 CHANGE)

### 기존 결정과 구현 전환
| 항목 | 기존 | 제안 | 라벨 |
|---|---|---|---|
| 발사 | 조준점 방향 가시 투사체, 독립 좌우 | 서버가 발사 요청 승인 후 **레이캐스트로 부착 판정**. 투사체는 시각만 | KEEP(판정 주체 CHANGE) |
| 줄 물리 | 휨·장력·흔들림 물리 표현 | **서버 판정 + 클라이언트 베지어 곡선 연출**. 실제 Rope 물리 제약 미사용 | CHANGE (C-02) |
| 당김 | 부착점 방향 끌려감 | 클라이언트가 당김 가속을 적용, 서버는 **당김 가속 상한**과 부착 상태만 검증 | NEW |
| 장애물 판정 대상 | 지형·건물·이동 오브젝트 | **알파: 고정 지형·구조물만**. 이동 오브젝트는 Should로 DEFER | CHANGE (C-03) |
| 사거리 | 직선거리 | 동일(KEEP). 초과 시 즉시 해제 | KEEP |
| 에너지 | 연결 중 지속 소모 | 동일. 0이면 해제, 관성 유지 | KEEP (2026-11-20 결정) |
| 재사용 대기 | 해제 후 짧은 대기, 실패에도 적용 | 동일. 초기 가설 0.8s | KEEP |
| 피격 시 끊김 | 강한 피격·특정 대상에서 끊김 | 피해 임계값 이상일 때 서버가 해제 | KEEP |
| 갈고리 파손 | 강한 충격·특수 조건만 | 알파는 **특수 조건 파손은 DEFER**, 수리 시스템만 구현 | CHANGE |

### 판정 흐름
1. 클라이언트: 버튼 누름 → 조준 방향(카메라 기준) 전송(Remote, 빈도 제한 10/s).
2. 서버: 쿨다운·에너지·상태 검사 → 레이캐스트 → 가장 가까운 대상 판정(뒤쪽 관통 금지, KEEP).
3. 성공 시 서버가 부착 상태를 기록하고 양쪽 클라이언트에 `RemoteEvent`로 통지. 실패 시 실패 피드백만.
4. 연결 중: 서버는 주기적으로 거리·에너지를 검사. 클라이언트는 당김을 적용.
5. 해제: 버튼 해제, 사거리 초과, 에너지 0, 피격 끊김, 대시 시작 중 하나.

### 두 갈고리 무입력 상태
- 기존 "균형 지향"은 알파에서 **두 지점의 중점 방향으로 약한 복원력**을 주는 단순 모델로 구현. 세부 물리는 DEFER.

### 성능 영향
- 갈고리 2개 동시 연결 기준: 서버 레이캐스트 2회/주기, Remote 상태 변화 이벤트만 발생. 연속 스트림 없음 → 네트워크 부담 낮음.
- 연출 줄: 클라이언트 전용 파트 2개 + 곡선 갱신. 기체 8대 기준에도 상시 물리 파트 0.

## 5. 무장과 발사

### 공통 발사 프레임워크 (KEEP 방향)
- 단일 `WeaponRunner`가 발사 입력 유형(단발, 자동, 점사, 충전, 홀드)을 데이터 테이블로 처리.
- 서버는 발사 허가만 판단하고 투사체 진행은 서버 틱에서 수행.

### 판정 방식 (알파)
| 방식 | 사용 무기 | 구현 | 비용 |
|---|---|---|---|
| 투사체(서버 레이 세그먼트 스텝) | 일반 사격, 자동 연사 | 매 틱 이동 구간을 레이캐스트 | 중간, 동시 200 상한 |
| 즉시 판정(히트스캔) | 정밀 사격 소형 | 발사 순간 레이캐스트 | 낮음 |
| 유도 투사체(저속, 타깃 고정) | 유도 무기 1종 | 타깃 ID와 갱신 주기 10Hz | 중간 |
| 광역 폭발 | 폭발탄 | 반경 내 부위 분배 계산 | 낮음 (발생 빈도 제한) |

- 조준: 일반 무기는 화면 중앙 자유 조준(KEEP). 유도 무기만 타깃 지정. 시야 밖 타깃은 해제.
- 발사 간격, 탄창, 재장전 시간은 무기 데이터 값(초기 가설 표는 `07` 부록).

### 투사체 규칙
- 물리 파트 없음(C-04). 서버가 틱당 이동량을 계산하고 레이캐스트 충돌 검사.
- 수명 상한 3초, 최대 사거리 상한 적용.
- 클라이언트에는 발사 시작 정보(방향, 속도, ID)만 전송하고 시각 보간.

## 6. 탄약, 재장전, 에너지 (KEEP 규칙, 구현 제안)

- 탄약: 종류별 **공용 예비 탄약**, 무기별 탄창(KEEP). 서버 상태만 진실.
- 재장전: 무기별 독립 타이머(KEEP). 동시 재장전 허용(KEEP). 강한 피격 시 해당 무장만 중단(KEEP).
- 강한 피격 임계값 초기 가설: **부위 최대 내구의 15% 이상 단일 피해**.
- 재장전 중 공격·대시·갈고리 제한(KEEP).

### 에너지 (2026-11-20 결정 전체 KEEP)
- 서버가 에너지 권위 보유. 클라이언트는 예측 표시만.
- 초기 가설: 최대 에너지 100, 회복 대기 1.0s 후 초당 25, 달리기 초당 15, 점프 1회 20, 대시 초당 12, 갈고리 연결 초당 6.
- 0 시 달리기·점프·대시·갈고리 금지, 기본 이동·전투는 허용(KEEP).

## 7. 부위 손상·파괴 판정

### 구조 (알파 축소안, CHANGE C-05)
| 구분 | 부위 | 알파 포함 |
|---|---|---|
| 장갑 존 | 정면, 좌, 우, 후 | 포함 |
| 기능부 | 다리(이동부), 주무장, 보조무장, 엔진, 센서, 제어장치 | 포함 |
| 특수 장비 | 기체 특수 장비 | DEFER |

- 기존 기획의 "다리 그룹 수 가변"은 알파에서 **다리 1그룹(4점 접지 레이)**으로 단순화.
- 기존 4단계 HUD 색상(정상·경미·심각·파괴) 유지(KEEP).

### 판정 흐름 (서버)
1. 명중 위치 → 장갑 존 선택(정면/좌/우/후, 방향 각도 기준).
2. 장갑 내구 감소 → 남은 피해가 있으면 **같은 공격의 초과 피해를 내부 부품으로 이전**(KEEP).
3. 직접 공격은 명중 기능부에 집중, 폭발은 반경 내 기능부 3개까지 분배(제안: 거리 가중치 60/25/15%, 【검증 필요】).
4. 부품 상태 전이: 정상 → 경미(내구 70%↓) → 심각(40%↓) → 파괴(0). 기능 저하 곡선은 데이터.
5. 연쇄 효과는 **직접 연결된 부품 1단계 성능 저하까지만**(KEEP). 무한 재귀 금지.

### 부품 연결 그래프 (알파 제안)
- 다리 → 엔진: 파괴 시 최대 속도 50%.
- 센서 → 주무장: 파괴 시 유도 무기 타깃 획득 불가, 직접 사격 정확도 저하.
- 제어장치 → 대시·갈고리: 파괴 시 해당 기능 비활성(KEEP: 대시와 연관 핵심 부품 파괴 시 대시 불가, 갈고리 장치 파손 규칙 포함).
- 주무장·보조무장 → 해당 무장 사용 불가.

### 기초 수치 (초기 가설)
| 부위 | 내구 | 방어값 |
|---|---|---|
| 장갑 존(각) | 400 | 가변 |
| 다리 | 200 | 낮음 |
| 엔진 | 150 | 낮음 |
| 주무장 | 180 | 중간 |
| 보조무장 | 160 | 중간 |
| 센서 | 120 | 낮음 |
| 제어장치 | 140 | 중간 |

- 수치는 프로토타입 전투 로그로 조정. 완성 피해 테이블은 알파 전 밸런스 시트로 관리.

## 8. 파일럿·파괴·부활 (KEEP 중심)

- 파일럿 체력 별도(KEEP). 초기 가설 100.
- 기체 파괴 시 파일럿은 탑승 상태 해제, 기체 잔해는 **마지막 위치에 파괴 상태로 남음**(KEEP: 별도 회수 절차 없음).
- 부활: 전투 불능 후 **10초 후 본부 또는 점령 전방 기지에서 부활**(초기 가설). 구조는 필요 없음(KEEP).
- 부활 후 비파괴 기체 직접 선택(KEEP). 마지막 기체 자동 선택 금지(KEEP).
- 새 기체 스폰 시 기존 자기 기체 제거(KEEP).

### 필드 수리 (KEEP 규칙)
- 수리 중 전투 행동 불가, 이동 불가. 중단 시 진행도 초기화, 재료 미반환(KEEP).
- 약한 공격은 무시, 강한 피격(임계값 §6)은 중단(KEEP).
- 수리 중 피해 감소·무적 없음(KEEP).
- 서버 타이머로 진행, 클라이언트는 표시만.
- 엔진·제어장치는 기지에서만 수리(KEEP).
