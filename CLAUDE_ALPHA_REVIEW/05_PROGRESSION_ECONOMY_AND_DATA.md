# 05. 성장·경제·데이터 설계

- 작성일: 2026-11-20 · 버전 v0.1 · 기준 `main` / `9d2d42b`
- 상태: 모든 제안 `PROPOSED — NOT APPROVED`. 수치는 초기 가설.

---

## 1. 목표

- 첫 세션에서 **"기체가 조금씩 강해지고, 다음 출격 전에 할 일이 생긴다"**를 느끼게 한다.
- 무료 플레이어도 핵심 콘텐츠와 기본 성장을 충분히 이용할 수 있어야 한다(KEEP).
- 경제 악용(복제, 중복 지급, 재화 무한 생성)을 서버 권위로 막는다.

## 3. 계정 레벨과 XP

- XP 획득: 임무 완료(주), 전투 기여(부), 탐험 발견(소). 분리 획득(KEEP: XP는 화폐와 별도).
- 레벨 역할(KEEP): 업그레이드 단계 상한 해금, 시설·기능 해금, 임무 요구 조건. **전투 능력치 직접 증가 없음.**
- 알파 곡선 (가설): 레벨 n 도달 필요 XP = 300 × (n−1)^1.3 (레벨 10 상한).
- 첫 세션 목표: 30분 플레이 시 레벨 2~3 도달.
- 군 계급은 알파 제외(KEEP: 스토리/특정 임무 한정으로 후속).

### 기체 기본 상한 (알파)
| 레벨 | 업그레이드 단계 상한 |
|---|---|
| 1 | 2 |
| 3 | 4 |
| 6 | 6 |
| 10 | 8 |
- 분야 5개(장갑·엔진·무장·센서·특수 장비, KEEP)는 **알파에서 특수 장비 분야를 DEFER**하여 4개 분야로 시작(CHANGE 소규모).

## 4. 업그레이드 (KEEP 규칙)

- 실패 없음, 성공 시에만 자원 소모(KEEP). 영구 적용, 다운그레이드 없음(KEEP).
- 분야별 독립 비용·재료(KEEP). 기체 간 이전 없음(KEEP).
- 알파 비용 곡선 (가설): 단계 k 비용 = 기본 화폐 200 × k^1.5 + 재료 k × 2.
- 초기 세션에서 1~2단계 업그레이드가 가능하도록 시작 화폐 설정(§6).

## 5. 수리 비용 (KEEP 구조)

| 상태 | 수리 방식 | 비용 가설 | 소요 |
|---|---|---|---|
| 경미 손상 | 자동 회복 (전투 중 느림 / 전투 외 보통 / 본부·점령 기지 빠름) | 무료 | 시간 |
| 심각 손상 | 기지에서 비용 지불, 즉시 완료 | 화폐 80 + 재료 3 (부품당) | 즉시 |
| 파괴 | 기지 수리, 심각 손상보다 **훨씬 비쌈** | 화폐 500 + 재료 12 (가설, 배수 약 6배) | 즉시 |
| 필드 일반 부품 | 파일럿 직접 수리, 일반 수리 재료 소모 | 재료 1~2 | 중단 규칙 KEEP |
| 엔진·제어장치 | 기지 전용 | — | — |

- 현장 수리 중단 시 재료 미반환(KEEP). 기지 수리 즉시 완료(KEEP).
- 파괴 기체 수리는 **원래 소유자가 부담**(KEEP). 임시 탑승은 DEFER이므로 알파에서는 발생하지 않음.

## 6. 신규 플레이어 첫 세션 경험

| 시점 | 상태 | 목표 행동 |
|---|---|---|
| 0~5분 | 저거노트 1대, 주무장 1·보조무장 1 선택(KEEP) | 이동·대시·갈고리 튜토리얼 조작 확인 |
| 5~15분 | 첫 임무 T1 완료, 자원 상자 2~3개 | 본부 복귀, 무장 변경 체험 |
| 15~30분 | 첫 업그레이드(1단계 무료 체험 쿠폰 형태 가설) | 수리 한 번 체험 |
| 30분 이후 | 레벨 2~3, 추가 무장 구매 가능 | 다음 출격 목표 설정 |

- 시작 자원 가설: 화폐 500, 재료 10, 탄약 기본 무제한(본부 무료 보충 KEEP).
- 추가 주무장 구매 가설: 화폐 800 (일반 화폐만, KEEP A안).

## 7. 탄약·보급 경제 (KEEP 구조)

- 기본 탄약: 기지 무료 보충(KEEP). 전방 기지도 기본 보급 허용(KEEP: 점령 기지 기능).
- 특수 탄약: 자원 지불(KEEP). 가격 가설 화폐 30~60 / 발.
- 현장 보급 차량(KEEP B안): 기본·특수 모두 보급 가능. 재고는 **차량 공용 총량 차감 + 일부 품목 개별 한도**(KEEP A+C 혼합).
  - 알파 가설: 공용 총량 120 발(기본), 특수 탄약 개별 한도 3회/임무.
- 차량 재고 보충: 임무 시작 시 1회 초기화(가설).

## 8. 설계도와 제작 (알파 DEFER)

- 알파는 저거노트 1종이므로 설계도 시스템을 구현하지 않는다.
- 단, **기체 해금 테이블**에 `unlock_source` 필드(기본 / 구매 / 설계도 / 스토리)를 두어 확장을 대비한다(NEW).
- 기존 결정 "무작위 확률 요소는 플레이 보상에만 허용(KEEP)"은 설계도 구현 시점에 적용.

## 9. 데이터 모델 (알파)

### 9.1 Account_v1
```
{
  v: 1,
  level, xp,
  currency, material,
  feldress: { [id]: { model: "M1A4", upgrades: {armor, engine, weapon, sensor}, unlocked_weapons: [...], equipped: {main, sub}, damage_state: {...} } },
  settings: {...},
  stats: {...}  -- 요약만
  updated_at, schema_check
}
```
- 탑승 중 상태, 에너지, 쿨다운, 투사체 등 **세션 상태는 저장하지 않음**.

### 9.2 WorldSlot_v1
```
{
  v: 1, slot_id, cycle_no,
  base: { state, facilities: {...} },
  zones: { [zone_id]: { owner, risk_score, last_update } },
  wave_no,
  updated_at
}
```

### 9.3 데이터 정합 규칙
- 재화 변경은 **트랜잭션 단위**(차감·지급·업그레이드 적용을 한 번의 UpdateAsync로 묶음 — 공식 권장: 구매 처리 시 즉시 저장 체크포인트).
- 중복 지급 방지: 보상 요청에 **보상 ID**를 두고 계정에 처리 완료 목록(최근 100개 가설)을 유지.
- 손상 감지: 스키마 검증 실패 시 **자동 덮어쓰기 금지**, 백업 키로 보존, 로비 "데이터 확인 중" 표시.

## 10. 악용 방지

- 재화 증가는 **서버 이벤트만**(임무 완료, 상자 수거, 판매 등). 클라이언트 요청으로 재화 변경 불가.
- 상자 수거는 서버에서 거리·상태·쿨다운 검사 후 지급.
- 업그레이드·수리·구매 요청은 **요청 ID 중복 제거**와 빈도 제한.
- 임무 보상은 임무 ID + 완료 토큰으로 1회만.
- 로그: 대량 재화 변동, 빈번한 실패 요청은 `Ops_v1`에 요약.
