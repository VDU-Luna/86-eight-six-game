## 2. 기술 위험 세부 대응

### R-01 / R-02 (이동 권한)
- 검증 파라미터: 샘플 주기 0.1s, 순간 이동 임계 = 한 샘플당 최대 이동거리 × 1.5.
- 보정: 서버가 "유효 위치"를 전송하면 클라이언트는 0.2초 보간으로 반영.
- 대안 측정: 완전 서버 시뮬레이션 프로토타입을 **비교용으로** 한 번 만들어 입력 지연 차이를 기록(구현 없이 측정 가능한 최소 버전으로).

### R-03 / R-04 (성능)
- 상시 상한과 저하 사다리는 `02` §11, `03` §4에 정의.
- 측정 지표: 서버 프레임 평균·p95, AI 틱 시간, 투사체 수, 물리 파트 수, 네트워크 KB/s.

### R-08 / R-09 (데이터)
- 저장 실패 3회 연속 시 해당 플레이어 세션을 **저장 보류 상태**로 두고 로비 복귀 우선.
- 세션 잠금 만료 시간 = 자동 저장 주기 × 2 (가설 240초) — 【검증 필요】.

### 3.2 부하 시나리오 (T-L 상세)
- **L1 기준**: 8명, 기체 8대, Legion 근거리 40 + 중거리 80, 투사체 200, 60분.
- **L2 상한**: 16명, 기체 16대, Legion 근거리 40 상한 유지, 투사체 400, 30분. 목적: 저하 사다리 동작 확인.
- **L3 저장 부하**: 8명 동시 접속 중 퇴장·재접속 반복 20회, 데이터 손실 0 확인.
- 측정: 서버 프레임(평균·p95), AI 틱, 물리 파트 수, 메모리, Remote 송수신량.
- 측정 도구: Developer Console의 서버 성능 통계, MicroProfiler(【검증 필요】 서버 측 캡처 범위와 제약), 자체 로그 집계.

## 4. 알파 통과·중단 기준

### 4.1 알파 통과 (모두 충족)
1. Must 기능 전부 구현, 명세 대비 테스트 100%.
2. T-S 데이터 손실 0, 중복 지급 0.
3. T-L L1 충족, L2에서 저하 사다리 정상 작동.
4. T-MB 모바일 실기기 3종에서 30fps 이상, 입력 실패율 < 5%.
5. T-LOOP 30분 내 완주, T-F 목표 달성 ≥ 80%.
6. 권한 우회 0건(T-X, T-P).
7. 출시 차단 버그 0건.

### 4.2 알파 중단 또는 재설계 조건 (하나라도 해당)
1. P-MOVE 검증을 적용해도 악용 또는 튕김이 해결되지 않음 → 이동 권한 모델 재설계(C-01 재검토).
2. 8인 L1에서 서버 프레임 p95가 목표를 지속 초과 → 기체·투사체 구조 축소.
3. 데이터 손실이 1건이라도 재현 → 저장 구조 재설계 전 제작 중단.
4. 모바일 입력 실패율 ≥ 15% → 모바일 입력 설계 재검토.

### 4.3 알려진 허용 제한 (알파에서 수용)
- 원거리 Legion 상태 튐 허용 범위 내 발생.
- 갈고리 줄 외형은 단순 연출.
- 서버 재시작 시 전투 상태 초기화.
- 서버 사이클 최종 작전 미구현.
