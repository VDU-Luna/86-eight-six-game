## 1. 원칙

- 모바일을 PC 축소판으로 취급하지 않는다. **입력 수 자체를 줄이는 것**이 1순위다.
- 전투 HUD는 기존 원칙(부위 실루엣 중심, 전체 HP 게이지 없음, 텍스트 경고 최소) 유지(KEEP).
- Roblox 공식 가이드(입력 유형 감지, 반응형 레이아웃, 터치 영역, 안전 영역) 준수【사실】.

## 2. 입력 설계

### 2.1 액션 목록 (Input Action System 기준, 【사실】 공식 입력 액션 시스템 지원)
| 액션 | PC | 모바일 | 컨트롤러 | 비고 |
|---|---|---|---|---|
| 이동 | WASD | 좌하단 가상 스틱(기본) | 왼쪽 스틱 | KEEP |
| 기체 회전 | 마우스 | 시점 드래그(우측) | 오른쪽 스틱 | 카메라 회전과 분리 |
| 주무장 발사 | 좌클릭 | 우측 큰 버튼 | RT | 홀드/탭 구분 |
| 보조무장 발사 | 우클릭 X | 우측 중간 버튼 | LT | KEEP 독립 |
| 좌 갈고리 | Q | 좌측 상단 버튼 | LB | 홀드 |
| 우 갈고리 | E | 우측 상단 버튼 | RB | 홀드 |
| 대시 | Shift | 더블 탭 대체 → **전용 버튼** | A | 쿨다운 표시 |
| 점프 | Space(홀드 차징) | 전용 버튼 홀드 | B 홀드 | 차징 표시 |
| 시점 전환(1/3인칭) | V | 메뉴 버튼 | 셀렉트 | |
| 재장전 | R | 무장 옆 소형 버튼 | X | 자동 재장전 KEEP |
| 상호작용(탑승·수리) | F | 문맥 버튼(화면 중앙 하단) | Y | 근접 시만 표시 |

### 2.2 모바일 제약 대응
- **동시 입력 한계**: 모바일 터치는 동시에 누를 수 있는 버튼이 실질적으로 3~4개. 따라서
  - 갈고리 좌·우 동시 발사는 모바일에서 **"양쪽 동시 발사" 단축 버튼**을 별도 제공(가설).
  - 대시 중 갈고리 연결 해제는 자동 처리되므로 추가 버튼 없음(KEEP 규칙 활용).
  - 점프 차징은 **탭 한 번 = 최소 점프, 홀드 = 차징** 방식 중 하나를 설정으로 선택 가능하게 한다(Should).
- 버튼 크기: 최소 터치 영역 9×9mm 이상(공식 접근성 권장 인용, 【사실】 Roblox 가이드가 WCAG 기준 언급).
- 엄지 자연 위치 기준 배치, 상단 모서리 버튼은 최소화.
- Roblox 기본 모바일 컨트롤(좌측 스틱, 우측 점프)과 충돌하지 않도록 **기본 컨트롤 비활성 후 커스텀**. 【검증 필요】: 기본 컨트롤 비활성 시 제약.

### 2.3 입력 유형 감지
- `PreferredInput` 변경 시 HUD 라벨 자동 전환(키 → 탭 → 버튼 표기). 【사실】 공식 가이드가 권장.
- 게임패드 연결 시 터치 버튼은 보조로 유지.

### 2.4 모바일 전용 단순화 (알파)
- 1인칭 콕핏 시점은 **모바일 기본을 3인칭**으로 두고 1인칭 전환을 허용(시야 가림 고려). 【제안·검증 필요】 기존 결정(1인칭 기본)과 충돌하므로 CHANGE C-13으로 기록.
  - 단, 콕핏 기본은 PC·컨트롤러 기본 유지.

## 3. 화면 구조

### 3.1 메인 메뉴 (KEEP 기존 결정)
- 정비고 3D 배경, 고정 카메라, 캐릭터 1명 + 대표 Feldress 1대.
- 좌측 세로 모드 카드 4개: 스토리 캠페인 / 오픈월드 / 멀티 미션(PvE) / PvP. 알파는 오픈월드만 활성, 나머지 어둡게 + '개발 중'.
- 화면 하단 또는 우측: 시작 버튼, 설정, 창고, 정비.
- 모바일: 카드는 하단 가로 스와이프로 전환.

### 3.2 정비 · 창고 (KEEP 전체 화면 전환)
- 정비: 좌측 기체 목록(이미지·이름·상태·레벨), 중앙 3D 모델 드래그 회전, 우측 업그레이드·무장·수리 탭.
- 모바일: 목록은 상단 가로 스트립, 상세는 하단 시트 패널.
- 창고: 화폐·재료·기타 3분류(§2 `05`).

### 3.3 전투 HUD (KEEP 우선순위)
| 우선순위 | 요소 | 위치 | 비고 |
|---|---|---|---|
| 1 | 부위 실루엣(1인칭) | 좌하단 | 4단계 색상 |
| 2 | 주·보조무장 탄창/예비, 재장전 상태 | 우하단 | 독립 표시 |
| 3 | 에너지 바 | 하단 중앙 | 0이면 강조 |
| 4 | 갈고리 좌·우 상태(사용 가능/연결/쿨다운/고장) | 중앙 하단 양쪽 | 줄 자체 표시가 기본(KEEP), HUD는 보조 |
| 5 | 대시 쿨다운 | 하단 우측 | 사용 불가 시 경고음만(KEEP) |
| 6 | 임무 목표 | 상단 우측 | 최소 텍스트 |
| 7 | 파일럿 체력 | 상단 좌측 | 별도 체력(KEEP) |

- 3인칭에서는 부위 실루엣 숨김(KEEP). 파일럿 체력·에너지·무장은 유지.
- **피격 피드백**: 임계 이상 피격 시 짧은 화면 흔들림 + 가장자리 붉은 빛(KEEP). 연속 피격은 병합(KEEP).
- **부품 파괴**: 강한 효과 + 실루엣 해당 부위 깜빡임 후 빨강(KEEP).

### 3.4 탑승 · 하차 · 수리 · 보급 표시
- 탑승 가능 거리 안에 들어오면 문맥 버튼 표시(KEEP: 상호작용 키).
- 하차는 **즉시 현재 위치에서**(KEEP). 안전 판정 없음.
- 수리 진행 바, 중단 사유 짧게 표시(강한 공격/이동 시도).
- 보급 차량 근접 시 재고 표시(공용 총량 + 개별 한도).

## 4. 오디오 설계 (알파 최소)

| 분류 | 사운드 | 방향 |
|---|---|---|
| 갈고리 | 금속성 짧은 연결음(KEEP), 발사음, 해제음 | 연결 성공만 효과음 강조(KEEP) |
| 무장 | 주무장·보조 독립 발사음, 재장전음 | 두 무장 구분을 위한 음색 차이 |
| 대시 | 짧은 추진음 | 사용 불가 입력 시 경고음 |
| 피격 | 임계 이상만 강한 금속음 | 연속 피격 병합(KEEP) |
| 파괴 | 부품별 다른 파괴음 | 알파는 3종 |
| Legion | 근접 기척, 발사음 | 원거리 집단은 **환경음 레벨로만** |
| 음악 | 메인 메뉴·전투 2트랙 | 전투 고조는 웨이브 발동 시 |

- 음향 우선순위 규칙: 동시 재생 상한 24, 낮은 우선도부터 제거.
- 3D 소스는 Legion·투사체 등 근거리에만. 거리 감쇠 설정.

## 5. 접근성

- 색각 이상 대응: 손상 4단계를 색 + **패턴 또는 아이콘**으로 중복 표시(알파 필수).
- 자막: 경고 음성은 알파에서 없음. 텍스트 대체 불필요, 모든 음성은 대사 자막 옵션을 둔다(NPC 대사 추가 시).
- UI 크기 조절 슬라이더 (HUD 0.8~1.3배).
- 카메라 흔들림 강도 옵션(0~100%). 끄기 가능.
- 모션 민감: 피격 빨강 가장자리는 강도 옵션.
- 콕핏 내부 표시 토글(KEEP).

## 6. 클라이언트 비용

- UI 애니메이션은 **TweenService 몇 개로 제한**, 상시 애니메이션 HUD 요소 최대 5개.
- HUD 업데이트는 **상태 변화 시에만**(매 프레임 갱신 금지). 에너지 바만 프레임 보간.
- 모바일 UI 레이어 수 상한과 ScreenGui 수 최소화(【검증 필요】 실측).

## 7. UX 검증 질문

1. 모바일에서 동시에 갈고리 2개 + 대시를 눌러야 하는 장면이 3초 이내에 빈번하게 생기는가?
2. 부위 실루엣만으로 "지금 무엇을 고쳐야 하는지" 판단 가능한가?
3. 에너지 0일 때 플레이어가 "왜 못 하는지"를 1초 안에 이해하는가?
4. 정비 화면에서 기체 상태와 다음 행동을 찾는 데 몇 초가 걸리는가?
