# Detailed Planning Backlog

상태: 기획 진행 중  
기준일: 2026-11-14  
원칙: 이 문서의 모든 설정은 임시이며, 사용자의 선택과 검토에 따라 언제든 변경할 수 있습니다. CONFIRMED는 현재 방향에 대한 합의이지 영구 고정이 아닙니다.

## 상태 표기
- CONFIRMED: 사용자가 현재 방향으로 선택한 항목
- PROPOSED: 검토를 위해 제안된 항목이며 확정되지 않음
- PENDING: 아직 결정하지 않은 항목
- DEFERRED: 장기 목표 등으로 현재 개발 범위에서 보류한 항목

## 기획 진행 원칙
1. 원작 자료에 명시된 설정, 2차 참고자료의 정리, 게임을 위해 새로 제안하는 설정을 구분합니다.
2. 원작 설정과 게임용 신규 설정이 충돌하지 않는지 확인합니다.
3. 사용자가 선택하지 않은 제안은 확정 설정으로 기록하지 않습니다.
4. 각 단계의 결정은 관련 문서와 Decisions Log에 함께 반영합니다.
5. 선행 단계가 결정되지 않은 후속 항목은 성급하게 확정하지 않습니다.
6. 핵심 기획 검토 및 사용자의 명시적 승인 전까지 제작·모델링·코딩을 시작하지 않습니다.

# 세부 의사결정 진행표

## 1단계 — 플레이어 시작 설정: 세부 질문 순서

### 1-A. 시작 시점의 세계관 상황
1. 플레이어의 이야기를 원작 연표의 어느 시기에 배치할지
2. 산마그놀리아 공화국의 86구역 체제 안에서 시작하는지, 그 체제의 붕괴·전환기에 시작하는지
3. 시작 지역과 당시 주변 정세를 어느 정도까지 원작 자료에 맞출지
4. 시작 사건이 원작 주요 사건과 직접 연결되는지, 같은 시기의 주변 사건으로 독립시키는지
5. 애니메이션 시즌 1·2 범위와 소설 이후 설정을 어떻게 구분해 다룰지

### 1-B. 플레이어의 초기 신분과 소속
1. 시작 시점의 법적·사회적 신분
2. 군 조직에 정식 편입된 상태인지, 임시 배속 또는 별도 상태인지
3. 소속 부대와 상위 지휘 계통
4. 플레이어가 처음부터 부대원인지, 도입 임무를 통해 합류하는지
5. 핸들러·지휘관·동료 NPC와의 관계
6. 원작 인물 또는 원작 부대와 접점이 있는지

### 1-C. 초기 부대의 성격
1. 정찰·경계·호위·전투 등 부대의 기본 임무 성격
2. 편제 단위와 부대 규모
3. 플레이어의 위치와 기본 역할
4. NPC 동료의 존재 및 역할
5. 다른 플레이어가 같은 부대에 들어올 수 있는 방식
6. 게임 서버의 플레이어 인원과 세계관상 부대 편제를 분리할지

### 1-D. 캐릭터 생성과 정체성
1. 플레이어가 직접 정할 수 있는 이름·호출부호
2. 외형 편집 범위와 세계관상 복장 기준
3. 배경 설정 선택이 게임 진행에 영향을 주는지
4. 초기 복장·장비의 선택 범위
5. 음성·대사 표현을 둘지, 텍스트 중심으로 처리할지
6. 생성 후 변경 가능한 항목과 변경 비용/제한 여부

### 1-E. 도입부와 첫 플레이
1. 시작 연출의 형식과 길이
2. 튜토리얼을 세계관 내 임무로 진행할지, 별도 훈련 공간에서 진행할지
3. 첫 임무의 목적과 완료 조건
4. 기본 이동·카메라·조준·타깃 지정·전술 명령을 소개할 순서
5. 실패 또는 중단 시 재시작 방식
6. 튜토리얼 종료 후 오픈월드에 진입하는 흐름
7. 솔로 플레이와 파티/조직 플레이의 도입 경험 차이

### 1단계 완료 검토
- 시작 시점이 원작 연표 및 참고자료와 모순되지 않는가
- 에이티식스 출신으로 시작한다는 기존 방향을 유지하는가
- 기아데 연방과 연결되는 과정이 자연스럽고 설명 가능한가
- 초기 부대가 이후 조직·계급·성장 설계의 기준이 되는가
- 신규 플레이어 캐릭터가 원작 캠페인 주인공의 역할을 침범하지 않는가
- Roblox의 플레이어 수와 서버 구조를 세계관상 부대 규모와 혼동하지 않는가

**1단계 최종 산출물:** 시작 시점 요약, 플레이어 신분 및 소속 설정, 초기 부대 개요, 캐릭터 생성 규칙, 도입부/첫 임무 개요.

## 각 단계의 대화 및 문서 갱신 절차
1. 해당 단계에서 가장 먼저 결정해야 할 질문 하나를 제시합니다.
2. 선택지별 특징·장단점·원작 정합성·구현 부담을 설명합니다.
3. 사용자가 선택하거나 수정 의견을 주면 해당 항목의 상태를 갱신합니다.
4. 연관된 결정과 충돌 여부를 확인하고 필요한 문서에 반영합니다.
5. 단계 산출물을 정리한 뒤 사용자 확인을 받고 다음 단계로 이동합니다.
6. 선택하지 않은 세부 내용은 임의로 확정하지 않고 PENDING으로 남깁니다.
